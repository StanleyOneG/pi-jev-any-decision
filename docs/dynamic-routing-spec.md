# Dynamic routing: agreed implementation contract

Status: implemented locally; original dynamic-routing baseline was 54c470f. The routing-efficiency update started from 043b7c4 and has separate offline evidence in [validation](dynamic-routing-validation.md). Existing repository-local debug logging is preserved. The bounded live evidence predates the efficiency update.

## Product decisions

The parent constructs a bounded set of dynamic execution options for the next stage, not a closed menu of three workflows. An option may describe serial, parallel or mixed work, consultation, partial delegation, independent review, or direct work. Always include one direct baseline. Jev compares submitted admissible options, not all possible plans. It never generates plans or explanations and never launches tools or changes permissions.

Quality and preservation of important constraints outrank cost. Evaluate task suitability, context dependency, where decisions are recorded (documents/conversation/both/unknown), handoff effort, loss risk, verification criteria/effort, execution effort, likely rework and benefit of independent review. Use bounded English summaries and categorical values including unknown, not invented dollar estimates or probabilities. Unknown is not favorable evidence.

The parent may prefer direct work after substantial requirements discussion because decisions, rejected alternatives and exceptions are expensive or risky to transfer. A large parent context alone neither requires delegation nor predicts quality. Serial independent work can be handed off: independence is not parallelism. A candidate's lower cost alone never establishes suitability. Independent review may be worthwhile even at comparable cost when it adds a concrete quality benefit.

Use role capabilities and configurable relative costs (lower/similar/higher/unknown), not child model names or hardcoded model prices. No role-name-based cost inference. Project config may provide defaults by purpose (execution/research/review) and per-role overrides; absent settings mean unknown. Role purpose and suitability must be explicit. Cost profiles are user assumptions, not measured savings.

Local code excludes options violating permission, availability, suitability/tool requirements or unresolved write conflicts. Exclude delegation of context-dependent work with confirmed high handoff-loss risk. Unknown transfer safety must not be treated as low risk: allow one bounded clarification/revision; if unresolved use a conservative direct fallback. Delegating a genuinely context-independent subtask remains possible even when the parent holds other sensitive decisions.

Jev returns a submitted option ID, insufficient_information, or revise_options. The last two are fixed classifier outcomes, not explanations. Parent interpretation and deterministic exclusion reasons must be distinguished from Jev output. Insufficient information means descriptions do not support comparison; revise_options means descriptions suffice but none is acceptable. A valid single direct option after filtering is permitted without manufacturing a delegation alternative. If only direct remains admissible and no unresolved transfer-safety clarification is pending, decide locally with reason `no_comparison`, no service call and no invented model confidence. Keep exclusion IDs/reasons in result details. If a filtered alternative has unresolved transfer safety, preserve the one-clarification flow rather than short-circuiting it.

Runtime owns the revision allowance, not a caller-provided attempt flag. Integration clarification: one clarification allowance is shared across the entire actual user request, because caller-provided phase labels cannot establish genuine task boundaries. This caps clarification invitations, not ordinary successful assessments of later stages. Cache hits and concurrent shared requests must not consume extra attempts or start duplicate calls. A caller must not reset the budget merely by changing phaseId. After the second abstention/uncertainty, return an explicit conservative local fallback and permit ordinary work. New actual user input resets the logical request and clarification budget, invalidates in-flight assessments, and retains only accepted advice where still applicable with its original context-count baseline; session lifecycle is respected. A reply/idle continuation by itself does not require reassessment. New meaningful phase, changed goal/scope/permissions/capabilities or growth requires explicit reassessment; the parent, not a raw-content classifier, identifies semantic transitions. No automatic repeated model calls.

Observe never blocks. Enforce and rules-only require a fresh assessment but must not force execution of the recommendation. Parent can record an English reason for choosing differently. Generalize the existing delegation_refuse behavior to any current recommendation, not only child launches. If helpful, tool instructions require recording a deviation; do not build a fake execution-plan validator from arbitrary shell calls. Existing host/subagent authority remains authoritative.

All natural-language fields submitted to TypeSafe must be English. Validate every visible submitted field before any service call, including ignored expanded direct fields, role names/capabilities, option summaries, evidence, criteria and a local-only no-alternative reason. Accept benign prose such as `token budget` or `password handling`; reject recognizable keys, explicit secret label/value pairs, bearer credentials and private-key headers. Use bounded ASCII identifiers and enumerations; reject non-English-script text and obvious secrets with repairable field-specific errors, without sending it. Simple guards cannot prove semantic English for ASCII text; document this limitation. No translator model, transcripts, code dumps, raw user messages or credentials. Local paths/config keys not sent to the service need not be English. SDK request/response logs stay opt-in, repository-local, no headers/API keys.

Preserve trust gating, off/rules-only behavior, session isolation, generation safety, cached snapshot semantics, cancellation, service-fallback visibility and parent smart-zone telemetry. Observe growth expiry also queues one non-triggering model-visible reminder per accepted assessment/expiry, not just a UI notice. Existing project mode/budget/debug config stays valid. Old boolean tool-call shapes may receive a clear migration error; do not silently infer favorable facts from legacy input. Update injected instructions, descriptions, documentation and tests together.

## Routing-efficiency interface and cadence (approved update)

External `delegation_assess` accepts `phase`, `phaseId`, bounded English `nextStep`, 1–8 `options` with one admissible direct baseline, optional `roles`, and optional `noDelegationReason`. Request/context telemetry is host-provided. A direct baseline needs only `id`, `kind: "direct"`, `summary`, `evidence`, `verificationCriteria`; omitted direct permission fields establish the admissible baseline only, never action authorization. Omitted comparison metrics are `unknown`. Expanded valid direct shapes remain compatible, but explicit invalid values, nonempty direct roles/tools and legacy `facts`/`selectedCandidate` are rejected. Delegated options still require all safety and comparison fields. With no delegated options supplied, require `{code, detail}` for `noDelegationReason`; codes are `trivial_continuation`, `no_authorized_delegate`, `no_suitable_delegate`, `handoff_not_worthwhile`, and detail is bounded ASCII English. It explains why no alternative was submitted, not a model refusal. A filtered delegated option does not require this reason.

For example, after initial capability discovery, a compact direct-only assessment can use:

```json
{"phase":"initial","phaseId":"small_edit_1","nextStep":"Update the located condition and verify its regression test.","roles":[],"options":[{"id":"direct","kind":"direct","summary":"Parent makes the bounded edit.","evidence":"The code seam and regression are already located.","verificationCriteria":"Run the focused test and inspect the diff."}],"noDelegationReason":{"code":"trivial_continuation","detail":"The remaining edit is too small to justify a separate handoff."}}
```

An omitted `roles` uses the last accepted role snapshot for this session; explicit roles replace it and `[]` clears it. Missing referenced roles get a repairable error. Successful capability rediscovery and session/tree/compaction resets invalidate the snapshot. Role cache entries are caller-provided capability evidence, not authority to launch; parent and host retain current permission responsibility. Retained accepted advice is similarly advisory, not an execution permit. Discover roles once initially and again when capabilities change; a phase is a meaningful work unit, not every tool output or user reply. Substantial research/code discovery should consider a bounded authorized delegated alternative or explain why none was offered. Explicit transitions, permission/capability change and configured context growth need reassessment. Context growth counts from the original accepted assessment across replies; unknown metrics do not invent expiry. `rules-only` and no-comparison skip Jev without changing the one-clarification rule.

Model-facing output is compact (`effective`, `origin`, `reason`, relevant revision/fallback action); full probabilities, parent-context telemetry and exclusions stay in `details`/opt-in debug. `details.source` distinguishes `local`, `rules`, `service`, `cache`, `in_flight`, and `serviceCalled` is true only for the initiating service path. Direct service payloads omit irrelevant role/tool/handoff fields and redundant direct safety defaults, preserve supplied relevant comparison evidence, and label omitted relevant facts `unknown`. The runtime does not inspect raw user content to detect semantic changes; the parent must supply bounded summaries rather than raw user content. Pi host session persistence of submitted tool arguments and imperfect ASCII-English/secret detection remain privacy limits.

## Validation and evidence

Offline tests: dynamic choice beyond three predefined workflows; grilling-context direct preference and high-risk exclusion; low-risk serial delegation allowed; independent review at comparable cost; unavailable/unsuitable/unauthorized/conflicting roles; unknown profiles and handoff facts; complete English/privacy validation; malformed distributions/unknown model choices; one-revision limit; concurrency/cache; stale completion/cancellation; enforce permits deviation; rules-only/off; debug regression.

Historically, at most 12 real TypeSafe smoke calls were authorized for the original feature; 6 were attempted (see validation). The routing-efficiency update authorizes **no new live API calls**. No automatic retry and no comparative child-execution benchmark. Parent owns any future budget decision; offline implementation performs no live calls. Use synthetic English scenarios, never private conversation. Capture count, request/response evidence, latency and observed versus intended outcomes. Report failures honestly; no claim of measured economic savings. Existing assessment calls for harness governance are distinct from the 12 experimental requests.
